## Next.js version warning

This project runs **Next.js 16.4 / React 19.3**, which has breaking changes relative to older training data. Before writing Next.js code, consult the bundled docs at `node_modules/next/dist/docs/` (`01-app/` covers the App Router used here) and heed deprecation notices. The `AGENTS.md` block is regenerated by `next dev`; commit it rather than removing it.

## Commands

- `npm run dev` — dev server at http://localhost:3000

## Architecture

Marketing site for Scrunity Labs, built with the App Router under `src/` (`@/*` resolves to `src/*`).

- **Config (`next.config.ts`)**: `cacheComponents`, `partialPrefetching`, `reactCompiler` (via `babel-plugin-react-compiler`), and `experimental.agentFeedback` are all on. Because the React Compiler is enabled, manual `useMemo`/`useCallback` is generally unnecessary. With `cacheComponents`, check the bundled docs for how dynamic data and caching must be handled in Server Components.
- **Styling**: Tailwind CSS v4, wired in through a Turbopack loader rule (`@tailwindcss/turbopack` on `*.css`), not PostCSS, so there is no `postcss.config` or `tailwind.config`. `src/app/globals.css` does `@import "tailwindcss"`. Fonts are Geist / Geist Mono through `next/font`, exposed as CSS variables on `<html>`.
- **Class merging**: use `cn` from the `cn` npm package (`import { cn } from "cn"`), a compiled clsx + tailwind-merge replacement. There is no local `lib/utils` helper.
- **Layout pattern**: `src/app/page.tsx` is a single long page split into anchored `<section id=…>` blocks. A `sections` array (`{ id, label }`) is the single source of truth: it is passed to `Sidebar` → `OnThisPage`, which runs an `IntersectionObserver` scroll-spy over those IDs. When you add a section, add it to the array and give the element a matching `id` plus `scroll-mt-14`. The left column is a sticky, full-height `aside` (hidden below `md`), and content sits inside `Container` (`max-w-239`, centered).
- **Client components**: `sidebar.tsx` and `on-this-page.tsx` are `"use client"`. The page and layout are Server Components. The active nav link in `Sidebar` is hardcoded to `/`, and most nav routes (`/services`, `/blog`, etc.) don't exist yet.
- `RootLayout` uses the generated global `LayoutProps<"/">` type for props (typed routes helper from Next.js).
